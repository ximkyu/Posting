Google Cloud — Schritt für Schritt (einmalig, ca. 10 Minuten)

  1. Google Cloud Projekt erstellen

    console.cloud.google.com/projectcreate → Projektname z. B. youtube-autoposter → Erstellen. Anschließend oben in der Leiste dieses Projekt auswählen.

  2. YouTube Data API v3 aktivieren

    Menü → APIs & Dienste → Bibliothek → YouTube Data API v3 → Aktivieren.

  3. OAuth-Zustimmungsbildschirm einrichten

    Menü → APIs & Dienste → Google Auth Platform (in älteren Konsolen: OAuth-Zustimmungsbildschirm).

    • Beim ersten Mal: Get started / Loslegen.
    • App-Name: YouTube AutoPoster, Support-E-Mail und Entwickler-E-Mail: deine eigene Adresse.
    • User type: External (für ein normales Google-Konto).
    • Scopes: nichts zwingend nötig — die App fragt den Scope {{ scopes|join(', ') }} beim Login selbst ab.
    • Audience → Publishing status: Testing → Add users → deine eigene Google-Adresse eintragen (sonst erscheint beim Login “Zugriff verweigert”).
  4. OAuth-Client erstellen — Typ: Desktop-App

    Google Auth Platform → Clients (bzw. APIs & Dienste → Anmeldedaten) → Client erstellen / Create credentials → OAuth client ID:

    • Anwendungstyp: Desktop-App (englisch Desktop app) — genau dieser Typ ist für dieses Projekt richtig. Er erlaubt den lokalen Redirect auf {{ redirect_uri }}, ohne dass du ihn eintragen musst.
    • Falls du stattdessen Webanwendung wählst, musst du unter Autorisierte Redirect-URIs exakt {{ redirect_uri }} hinterlegen.
  5. credentials.json herunterladen und ablegen

    Beim neuen Client: JSON herunterladen. Die Datei umbenennen in credentials.json und hier ablegen: 

    {{ settings.CREDENTIALS_DIR }}\credentials.json

    Vollständiger Pfad: {{ config_description.CLIENT_SECRETS_FILE }} relativ zum Projektordner bzw. <Projekt>\credentials\credentials.json. Die Datei steht in .gitignore und wird niemals versioniert.

  6. Programm starten

    Doppelklick auf start.bat (bzw. ./start.sh).

  7. YouTube-Konto autorisieren

    Dashboard → Google-/YouTube-Konto einmalig verbinden → Browser → Google-Konto wählen → bei “Google hat diese App nicht überprüft” auf Erweitert → Weiter zu YouTube AutoPoster (nicht sicher) → Zulassen.

    Danach liegt das Token lokal (unter Windows DPAPI-verschlüsselt). Ein Passwort wird nie gespeichert, abgelaufene Access-Tokens erneuert die App automatisch über das Refresh-Token.

  8. Fertig — READY-Ordner verwenden

    Video + JSON (+ optional Thumbnail) in {{ config_description.READY_FOLDER }} legen.

Wichtig: private Videos & API-Audit

Dieses System lädt immer privat hoch — das ist Absicht und harte Regel. Zusätzlich gilt eine YouTube-Richtlinie, die du kennen solltest:

Alle Videos, die über videos.insert aus nicht überprüften API-Projekten hochgeladen werden, die nach dem 28.07.2020 erstellt wurden, bleiben von YouTube privat gesperrt. Der Button VERÖFFENTLICHEN liefert dann einen Fehler (z. B. forbiddenPrivacySetting / “restricted to private viewing mode”).

Lösung: das Projekt einmalig von YouTube auditieren lassen — YouTube API Services – Audit- und Quota-Formular. Das Formular wird auch für mehr Tageskontingent benutzt. Nach der Freigabe funktioniert VERÖFFENTLICHEN wie vorgesehen.

Bis dahin bleiben deine Uploads privat — du kannst sie jederzeit im YouTube Studio manuell öffentlich schalten. Das System zeigt diesen Fall klar als Fehlermeldung an.
